## What This Repository Is

Optimized Snakemake pipeline for **HyperTRIBE** — identifying RNA-binding protein
(RBP) targets by detecting A-to-G RNA editing introduced by an RBP–HyperADARcd
fusion protein expressed in cells. Compares treatment (HyperTRIBE) BAM files
against control (wildtype or gDNA) BAM files to find statistically enriched
editing sites, then annotates them with gene information.

**Owner**: Jeetayu Biswas, MD — MSKCC Molecular Pharmacology / Leukemia Service  
**GitHub**: github.com/jeetayu/HyperTRIBE (branch: snakemake-slurm, now default)  
**HPC scheduler**: SLURM (sbatch)  
**Reference genome**: hg38 (primary), mm10 supported

## Pipeline Flow (10 Snakemake Rules)

```
FASTQ → fastp_trim → star_align → index_bam
                                       ↓
                          call_editing_sites  ← parallel, all control + treatment BAMs
                                       ↓
                          filter_replicates   ← sites must appear in ≥ min_replicates
                                       ↓
                          annotate_genes      ← adds gene_name, gene_id, biotype from GTF
                                       ↓
              ┌────────────────────────┼──────────────────────────┐
    extract_target_genes    compile_alignment_stats   3 plot rules
              └────────────────────────┼──────────────────────────┘
                                       ↓
                          generate_report     ← quarto render notebooks/hypertribe_report.qmd
```

**Key script design notes:**
- `call_editing_sites_parallel.py` outputs **one BED row per (position × treatment replicate)**
  that passes thresholds. So each genomic position appears N times (N = treatment replicates).
- `filter_replicates.py` groups rows by position, counts N, and pools counts to recompute
  edit frequency and p-value on the merged data.
- `annotate_genes.py` has a **biotype priority fix** — prevents generic ncRNA classes
  (e.g. Metazoa_SRP) from overriding protein-coding gene annotations.
- The Snakefile uses `workflow.basedir` for all script paths, so it can be invoked from
  any analysis directory: `snakemake --snakefile /path/to/Snakefile --configfile config.yaml`

## First-Time HPC Setup

```bash
# 1. Clone (default branch is snakemake-slurm)
git clone https://github.com/jeetayu/HyperTRIBE.git
cd HyperTRIBE

# 2. Run the interactive setup wizard
#    Prompts for: SLURM account, partitions, reference paths, sample names
bash setup.sh

# 3. Install conda environment (one-time, ~10 min)
conda env create -f environment.yml
conda activate hypertribe

# 4. Install Quarto CLI (one-time, separate from conda)
#    https://quarto.org/docs/get-started/

# 5. Put FASTQ files in:  data/fastq/{sample}_R1.fastq.gz
#                         data/fastq/{sample}_R2.fastq.gz
#    Names must match sample names in config.yaml

# 6. Dry run
snakemake --profile slurm --configfile config.yaml -n

# 7. Submit
sbatch submit_pipeline.sh
```

```yaml
# Sample names must match FASTQ filenames exactly
control_samples:   ["ctrl_rep1", "ctrl_rep2"]
treatment_samples: ["ht_rep1", "ht_rep2"]

# HPC paths — must be absolute
genome:     "/path/to/hg38.fa"
star_index: "/path/to/STAR_index/hg38/"
annotation: "/path/to/gencode.v45.annotation.gtf"

# Thresholds
min_coverage:    20     # minimum reads at a position
min_edit_freq:   0.05   # 5% editing minimum
edit_fold_change: 2.0   # treatment/control editing ratio
min_replicates:  2      # must appear in ≥2 treatment replicates
```

## SLURM Configuration

Two files control cluster submission:

**`slurm/cluster.yaml`** — replace placeholders before first run:
```yaml
__default__:
  account:   "YOUR_SLURM_ACCOUNT"    # ← replace
  partition: "YOUR_PARTITION"         # ← replace

call_editing_sites:
  partition: "bigmem"                 # ← needs ≥128 GB RAM node
  mem: "128G"
  time: "48:00:00"
```

**`slurm/config.yaml`** — Snakemake profile, usually no edits needed.

To monitor jobs:
```bash
squeue -u $USER
tail -f logs/slurm/snakemake_controller_*.out
```

>70% unique mapping rate, enrichment in 3′ UTRs.

## Common Issues and Fixes

**No editing sites found**
- Check STAR alignment quality: `cat aligned/*.Log.final.out`
- Confirm treatment/control assignments in config.yaml are not swapped
- Try lower thresholds: `min_coverage: 10`, `min_edit_freq: 0.03`

**STAR runs out of memory**
- Reduce sort RAM: `--limitBAMsortRAM 16000000000` in Snakefile star_align rule
- Or increase bigmem partition memory in `slurm/cluster.yaml`

**Quarto render fails**
- Confirm `quarto` is in PATH: `which quarto`
- Confirm Jupyter kernel is registered: `python -m ipykernel install --user`
- Fallback: run Python report instead:
  ```bash
  python scripts/generate_report.py \
    --editing-sites results/annotated_editing_sites.bed \
    --alignment-stats results/alignment_stats.txt \
    --gene-list results/target_genes.txt \
    --gene-ranks results/target_genes_by_editcount.txt \
    --output results/analysis_report.html
  ```

**Pipeline resumes after failure**
```bash
# Snakemake tracks completed steps — just resubmit
sbatch submit_pipeline.sh
# or locally:
snakemake --profile slurm --configfile config.yaml --rerun-incomplete
```

**Annotated sites show wrong gene names**
- This is the biotype priority bug (fixed in annotate_genes.py)
- Confirm you're using scripts/annotate_genes.py from this repo, not legacy/CODE/

## Key Parameters Reference

| config.yaml key | Default | Effect |
|---|---|---|
| `min_coverage` | 20 | Minimum reads at a position in control+treatment |
| `min_edit_freq` | 0.05 | Minimum A→G editing rate in treatment (5%) |
| `edit_fold_change` | 2.0 | Minimum ratio treatment/control editing |
| `p_value_threshold` | 0.05 | Fisher's exact test cutoff |
| `min_replicates` | 2 | Treatment replicates a site must appear in |
| `calling_threads` | 16 | CPUs for parallel editing site calling |
| `chunk_size` | 10000000 | Genome chunk size for parallelisation (10 Mbp) |
| `star_threads` | 8 | CPUs per STAR alignment job |

## Development Notes

- All scripts import from stdlib + conda env; no local package installs needed beyond environment.yml
- `filter_replicates.py` uses scipy.stats.fisher_exact for pooled p-value recalculation
- `annotate_genes.py` uses a simple sorted-list interval search (no interval tree dependency)
- The Snakefile rule `generate_report` passes `--execute-dir` to Quarto so relative paths
  (results/, config.yaml, qc/) resolve from the analysis working directory, not the Snakefile location
- `workflow.basedir` is set at Snakefile import time — always the directory containing the Snakefile
